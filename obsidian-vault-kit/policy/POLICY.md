# Obsidian Vault 운영 정책 (재사용 가능한 일반 규칙)

개인용 Obsidian vault를 관리하면서 정리한 규칙들 중, 특정 vault의 폴더 구성(가족/자산 등 개인 카테고리)과 무관하게 **어떤 vault에나 그대로 적용 가능한 부분만** 추려서 정리한 문서입니다. 실제 폴더 구조(대주제 목록 등)는 vault마다 다를 수 있으므로 이 문서에는 포함하지 않았습니다 — 아래 규칙을 적용할 때는 각자의 vault 구조에 맞게 대입하세요.

## 폴더 명명 원칙
- 대주제(최상위) 폴더는 번호 없이 이름만 사용
- 하위 순서가 있는 폴더는 `01-`, `02-` 처럼 숫자+하이픈 접두사
- 특수/메타 폴더·파일(템플릿, 첨부파일 모음, AI 생성 위키 등)은 언더스코어(`_`) 접두사로 구분해 일반 콘텐츠 폴더와 시각적으로 분리 (예: `_templates`, `_attachments`, `_index.md`)
- 외부 도구가 고정된 폴더명을 요구하는 경우(그래프 생성 도구의 산출물 폴더 등)는 그 도구의 명명 관례를 예외로 따르고, 대신 Obsidian 설정의 "제외된 폴더"에 등록해 검색·그래프뷰에서 빠지게 처리

## 파일(노트) 명명 원칙
- 파일명 구성요소 구분은 언더스코어(`_`)로 통일 (예: `260830_주제_세부주제.md`)
- 하이픈(`-`)은 예외적으로만 허용: ①원문 제목/고유명사에 하이픈이 포함된 경우, ②영문 고유명사(제품명·프로젝트명 등)
- **기존 파일명은 새 규칙에 맞춰 일괄 리네이밍하지 않는다** — 그래프 분석 도구(Graphify 등)가 노드 ID를 파일 경로 기반으로 생성하는 경우, 파일명을 바꾸면 그래프가 깨져서 전체 재빌드가 필요해진다. 명명 규칙은 신규 문서부터 적용하고 기존 파일은 그대로 둔다

## frontmatter 작성 정책
- 공통 필드(예: 분야/주제/태그/날짜/관련 노트) 세트를 `_templates/frontmatter-template.md` 하나로 관리하고, 노트 작성 시 이를 참고해서 채운다 — AI 에이전트에게 필드 목록을 통째로 기억시키지 말고 항상 템플릿 파일을 읽게 하는 것이 원칙(템플릿이 바뀌어도 별도 동기화 없이 항상 최신 반영됨)
- 특정 카테고리(예: 외부 영상 요약)처럼 공통 필드 위에 전용 필드가 추가되는 경우, 별도의 하위 템플릿 파일(`_templates/<카테고리>-frontmatter-template.md`)로 분리해서 관리
- 배열형 필드(태그, 관련 노트 등)는 값이 없을 때 빈 배열(`[]`)로 남겨두는 것과, 필드 자체가 없는 것을 구분해서 취급 — 전자는 "아직 없음"이라는 정상 상태, 후자만 "누락"으로 판정
- 노트 간 참조(백링크)는 본문에 별도 섹션(`## 관련 문서`)을 만들지 않고 frontmatter의 관련 필드로 처리 — 위키링크 문법(`[[노트명]]`)을 그대로 배열에 넣으면 Obsidian이 인식하는 진짜 링크가 된다

## 클리핑/스크랩 이미지 저장 기준
웹 클리핑이나 외부 콘텐츠를 노트로 옮길 때, 원문의 이미지를 전부 저장하지 않는다 — 요약·분석 내용을 이해하는 데 실제로 필요한 이미지만 판단해서 골라 저장한다. 무분별한 이미지 저장은 vault 용량과 검색 노이즈를 늘릴 뿐 정보 가치를 더하지 않는 경우가 많다.

## 오디오 녹음 처리 기준
음성 메모 등을 녹음해 노트화하는 경우, 텍스트 변환(전사)이 끝나면 원본 오디오 파일과 노트 내 임베딩은 기본적으로 삭제한다 — 텍스트만 남기고 오디오는 보관하지 않는 것이 기본값. 원음 자체가 반드시 필요한 예외적인 경우에만 사용자 확인 후 보관한다.

## Obsidian 확장 마크다운 문법 적용 정책
콜아웃(`> [!note]`, `> [!warning]` 등), 하이라이트(`==텍스트==`), 블록 참조(`^block-id`) 같은 Obsidian 확장 문법은 **새로 작성하는 노트부터** 적용하고, 이미 존재하는 노트를 이 문법에 맞춰 일괄 리포맷하지 않는다 — 내용이 바뀌면 그래프 분석 도구가 해당 파일을 재처리 대상으로 인식해 불필요한 비용이 발생할 수 있기 때문. 다른 사유로 어차피 그 노트를 편집하게 될 때만 자연스럽게 함께 반영한다. frontmatter 필드명은 이 문법 스킬(예: `obsidian-markdown`)의 예시가 아니라, 각 vault의 `_templates/` 규칙을 그대로 따른다 — 문법 스킬은 마크다운 문법 메커니즘만 참고하고 필드명까지 따라가지 않는 것이 핵심.
- 각주(`[^1]`) 문법처럼 vault 설정(코어 플러그인 등)에 따라 렌더링이 안 되는 문법은 사용하지 않는다 — 적용 전 실제 vault 설정에서 지원되는지 먼저 확인
- 주기적으로 갱신되는 요약/위키 문서는, 다음 갱신 때 새로 추가되는 섹션부터 새 문법을 적용하고 기존 섹션은 그대로 둔다(문서 전체를 일괄 리포맷하지 않는다는 원칙의 연장)

## AI 에이전트(Claude Code 등)와 함께 vault를 관리할 때
- vault 자체를 git 리포로 관리하면, AI 에이전트가 편집 후 자동으로 커밋·푸시하도록 지침을 줄 수 있다 — 이 경우 여러 기기(PC/모바일)에서 동시에 편집이 들어올 수 있으므로, 편집 전후로 반드시 원격 브랜치를 fetch해서 동시 커밋 여부를 확인하는 절차를 습관화한다
- AI가 자동 생성/갱신하는 문서(통합 위키 등)는 "사람이 직접 편집 금지, 재생성 요청으로만 갱신" 같은 명시적 규칙을 frontmatter 경고문으로 문서 상단에 남겨 사람이 실수로 덮어쓰지 않게 한다
- 민감정보가 있는 폴더(가계부·매매일지 등)는 요약·재해석 대상에서 명시적으로 제외하고, 자동화 도구(그래프 생성기 등)의 ignore 설정에도 동일하게 등록해 이중으로 보호한다
